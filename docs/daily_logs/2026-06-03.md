## 1. 오늘의 작업 목표

화성시 작은도서관 데이터와 화성시 인구 데이터를 “주소” 기준으로 join_key를 설계한다. 

—

## 2. 발생한 문제

화성시 인구 데이터 csv의 컬럼을 기준으로 “동”,”읍”,”면”매핑하려 했으나,
화성시 작은 도서관 데이터의 도서관 주소지가 “구” 기준으로 입력된 경우가 있었다. 

이로 인해 두 데이터를 바로 join하기 어려워, 수동으로 매핑해야하는 상황이 발생했다.

—

## 3. 문제 해결 과정

작은도서관 주소 데이터는 구·읍·면 기준으로 매핑하고, 인구 데이터도 같은 기준으로 집계한 뒤 join하는 방향으로 수정한다

—

## 4. 오늘 배운 점 

join을 하기 전, 두 데이터의 지역 단위가 같은지 확인 후, 같은 join_key 기준으로 맞춘 뒤 결합해야 한다.


## 추가로 발견한 문제

일부 주소는 `효행구 봉담읍`처럼 구와 읍이 함께 표기되어 있었다. 
초기 코드에서는 봉담읍을 먼저 인식해 `매핑_행정구역`이 봉담읍으로 저장되었지만, 
다른 주소는 `효행구 기안동`처럼 세부 지역명이 목록에 없어 null로 남았다.

이 상태로는 join_key가 `봉담읍`, `효행구`, `동탄구`처럼 서로 다른 행정 단위로 섞일 수 있다.

따라서 1차 분석에서는 `join_key`를 구 기준으로 통일하고, 
봉담읍·기안동 같은 세부 지역명은 `region_detail` 컬럼에 별도로 보존하기로 했다.

## 5. 코드 변경 기록

초기 버전에서는 주소에서 읍·면·동 이름을 직접 찾아 `매핑_행정구역`에 저장했다.

하지만 원본 주소가 `동탄구`, `병점구`, `효행구`처럼 구 단위로 표기된 경우가 많아,join_key가 읍면동과 구 단위로 섞이는 문제가 발생했다.

따라서 기존 코드는 `src/archive/add_mapping_columns_v1_area_mapping.py`에 저장하고, 현재 실행용 코드는 구 기준 join_key를 생성하는 방식으로 수정했다.
